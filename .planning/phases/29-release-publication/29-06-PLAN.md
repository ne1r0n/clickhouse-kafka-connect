## Execution environment

- **Who runs what (PT-12).** The orchestrator runs this plan inline; it is not dispatched to a `gsd-executor` as a whole, because an executor has no Agent tool and cannot spawn the reviewer, and an executor's own reading does not count as independent. The orchestrator spawns `gsd-code-reviewer` with the Agent tool, one fresh agent per round, with the brief as its prompt. Fixes are applied by a `gsd-executor` that the orchestrator dispatches with a fix-only prompt (the finding IDs with their verbatim `### ID: title` lines, the allowed files, the checks to re-run, and the rule that it does not review). Tasks 1 and 3's bookkeeping may run inline. GSD lives under `~/.claude`: any snippet that requires `./gsd-core/bin/lib/...` is pointed at `~/.claude/gsd-core/bin/lib/`.
- Plan 29-01's Execution environment applies (fixed SHAs, Gradle prefix, shell traps, evidence format). `P29_BASE = c1dc6e5983fe93745526cecd89d3b7e7cff63c7d` is the review's `diff_base`.

Evidence map: `29-COMMAND-EVIDENCE.md` and the Phase 25-28 evidence it cites.
- **Fix-text rule (D-09).** Every key form, query, command or number that a reviewer proposes is checked against the connector code and the evidence before it is applied (Phase 24: a proposed `enableDbTopicSplit` key form was wrong). A changed query or command is re-proven through the probe of plans 29-02 and 29-03 (worktrees under `/tmp/gsd29`, re-created if gone) and recorded as a new evidence entry from `### E-50:` on.

Set `deferred` by hand with the reason in the Source cell (no `|` in it), and add the finding as `### 29-REVIEW <ID>: <title>` with Reason, Owner, Re-open trigger and Source to a `## Carried from the Phase 29 review` section of the close record, placed after `## Other carried items`, so the 16-entry carried section of plan 29-05 and its check stay unchanged.
