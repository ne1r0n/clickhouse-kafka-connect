The orchestrator spawns a continuation executor (execute-phase checkpoint handling), which checks the Task 1 commit with `git log`, redoes nothing and runs Task 2. Only the Task 2 executor writes the SUMMARY.
4. **The hand-off approves nothing.** It is a dynamic context boundary, like an auth gate, not a planned checkpoint task and not one of the phase's approval gates.
