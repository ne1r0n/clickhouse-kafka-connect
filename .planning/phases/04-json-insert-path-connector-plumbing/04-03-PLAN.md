<objective>
Cover the connector-level fork changes: MBean naming and per-task registration (JMX-01..04) and
`async_insert` left to the user (ASYNC-01..03). This plan carries the phase's single pre-approved
main-code change — extracting `buildMBeanName` out of `ProxySinkTask.getMBeanName()` so JMX-03's two
branches become reachable at all.

Purpose: today `getMBeanName()` is private, reads the client jar's implementation version inline, and
is only reachable through a constructor that requires a live ClickHouse. The real client jar reports
a plain version like `0.9.6`, so the null-version and colon-in-version branches can never execute in
a test. The fork's `async_insert` change is one commented-out line whose effect is entirely visible
in the settings map the config builds.

Output: one package-private static helper, two Docker-free test classes, two ClickHouse-backed test
classes, and no other production change anywhere.
</objective>

<assumption_delta_decision>
## Assumption delta — the `pluralization` signal on MBean identity

**Signal:** "multiple tasks and connectors register distinct MBeans, and each `stop()` unregisters
only its own" (JMX-04). What reads as one anchor — `connector=<name>` — is not an identity at all
once more than one task exists.

**The noun that is now primary:** not the connector name but the **full ObjectName**, whose identity
is the pair (`connector=<name>`, `name=SinkTask<id>`), where `id` comes from a process-global
`AtomicInteger NEXT_ID` that never resets inside a test JVM fork. The connector name alone is a
*filter predicate*, not a key: two tasks of one connector share it.

**Decision: `promote` — at the level of how the tests name and assert identity only.** JMX-04
treats the whole `ObjectName` as the identity key: it identifies a task's MBean by the
single-element set difference between the snapshot taken after that task started and the one before,
asserts distinctness across all four ObjectNames, and asserts which ObjectName disappeared after a
single `stop()`. The connector name is used exclusively as the filter that narrows the platform
server's global query to this test's own MBeans.

**Explicitly NOT a main-code change.** The connector's own identity model is untouched: no change to
`NEXT_ID`, to the `id` field, to the format template, or to `MBeanServerUtils`. A main-code identity
change would be an escalation under D-01, and this phase pins current behavior. The promote is
confined to the vocabulary and the assertion strategy of the tests, which is precisely what D-04
already prescribes when it rules out absolute names such as `SinkTask0`.

**What this buys:** the test cannot be written in the naive form ("assert the MBean named
`connector=X` exists") that would pass with one task and silently mean nothing with two.
</assumption_delta_decision>
