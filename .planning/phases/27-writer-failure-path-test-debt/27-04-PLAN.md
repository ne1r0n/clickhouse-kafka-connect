## Decisions recorded in this plan

- **The guard's form (D-14, Claude's discretion).** It is a Docker-free unit test in `src/test/java/com/clickhouse/kafka/connect/ci/`, not an addition to `verify-merge-invariants.sh`. That script and its self-test are read-only in this milestone, and the guard has nothing to do with merge provenance. It scans `src/main/java` only (D-11 keeps the test tree out). Its pattern is wider than ID-shaped tokens, because three hits are not ID-shaped (`Phase 28's`, `RESEARCH` / `Pitfall 4`, `backlog 999.4`). The pattern self-test keeps a regex typo from making it vacuous.
- **An anchor for D-09.** The refactor adds the row `WRITE_TYPE_MISMATCH_FAILURE_FORMAT` 2 (WRT-19). An upstream sync that brings back the inline format would then fail the gate instead of silently re-opening the drift risk. Research expected no WRT-19 anchor; this one is additive.
- **The FORK-DELTA note for the changed upstream line.** The doWriteColValue row says the `ClassCastException` text is now built from the shared prefix and helpers, with text byte-identical to upstream's, so the next syncer expects the conflict. A Test-harness row names the guard.
- **Scrub commit grouping.** There are two comment-only commits: the writer path (ClickHouseWriter, WithheldMessageException) and the rest (six files). Each is compiled on exactly its own tree: the uncommitted guard file is moved out of `src/test` while they are made.
- **Tracer.** Not used: a pin-first refactor of an existing path (Phase 26 precedent). The phase tracer is plan 27-01 Task 1.
- **Not split, despite the 130k estimate and 13 files (scope).** The estimate is low-confidence (no calibration samples), and most of it is Gradle and verify output. Every file in `files_modified` is edited, so none can be trimmed. ClickHouseWriterColumnContextTest, fork-anchors.txt and the evidence file are edited in Task 1. ClickHouseWriter is edited in Tasks 1 and 2, and FORK-DELTA in Tasks 1 and 3. The seven other src/main files take comment-only scrub edits of one to four lines each in Task 2, and HeaderToValue also takes the reverted plant of Task 3. The guard is new in Task 2. A split into pin-and-refactor and scrub-and-guard is possible, but it is not cheap. It would renumber plan 27-05 and its evidence IDs E-11..E-13, and every cross-plan count reference. It would not lower the cost of any single task. The locked order and the plan's commit sequence are the same either way.
