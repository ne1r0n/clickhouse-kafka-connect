## Planner decision PD-02 — one of the thirteen has no getter and no ConfigDef entry

D-15 specifies that the CFG-03 test "asserts each of the thirteen getters returns upstream's default". Verified against the merged file at planning time, that is true for twelve of them but **not** for the connector retry timeout (`errors.retry.timeout`, key constant `CONNECTOR_RETRY_TIMEOUT` at line 66). That option has:

- no `private final` field and therefore **no** Lombok-generated getter;
- **no** `configDef.define` entry at all (confirmed: every other twelve have exactly one, this one has zero);
- a single consumer — the constructor reads it into a local at line 335 with the literal default `"60000"` and uses it only to emit a warning when the configured value is below the minimum-threshold constant.

**Decision:** the test asserts twelve getters, and covers the thirteenth by asserting the two things that are actually observable for it — that its key constant exists with the expected key string, and that constructing a config from the minimal props map with the key absent completes without throwing and emits no warning-path failure. The SUMMARY's inventory table names the option, its literal default, its consumer, and the fact that it is neither getter-backed nor `ConfigDef`-declared. CFG-03's requirement text — "present and reach their consumers at their upstream defaults" — is satisfied honestly this way; asserting a getter that does not exist would not be.

Reversibility: reversible. If a later phase gives the option a field and a definition, the test gains a thirteenth getter assertion and the inventory note is removed.
