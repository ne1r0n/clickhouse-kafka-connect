## What retry classification reads (the invariant the rebuild keeps)

From `Utils.handleException` and `Utils.getRootCause(e, true)` (read them; do not change them), after Processing wraps the writer's exception X in `RuntimeException(queryId, X)` and client V2 wraps X in `com.clickhouse.client.api.ClickHouseException` when, and only when, X is a RuntimeException:
- R1, the top category: whether X is an IOException or a RuntimeException (it decides the V2 wrap).
- R2, the classified root: the first link from the top that is a client V1 `com.clickhouse.client.ClickHouseException` or a client V2 `ServerException` (its error code is read), otherwise the deepest link (its type is read for `SocketTimeoutException`, `UnknownHostException`, `SocketException` and `IOException`, and an IOException's message for the read- or write-timeout prefix at index 0).
- R3: whether any link is a `RetriableException`.
The top-level `DataException` check never sees the writer's exception, because Processing always wraps it. A Jackson link is an IOException of no socket or server type; above the classified root its type is read by none of R1-R3 except as the top (R1), and as the root (R2) only through "IOException" and its message prefix.
