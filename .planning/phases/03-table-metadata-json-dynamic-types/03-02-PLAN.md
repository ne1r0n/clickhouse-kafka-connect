<objective>
Prove that `JSON`, parameterized `JSON(...)` and `Dynamic` columns — the fork's headline type support — map
correctly and round-trip real data on ClickHouse `latest` through both insert routes that remain available
once the RowBinary path starts failing fast, including non-ASCII values under the `windows-1252` test JVM.

Purpose: today's `JsonColumnTest` asserts only `countRows`, so a `JSON` column could silently hold the wrong
nested value and a `Dynamic` column could silently hold `42` as a `String` with the suite still green. D-14
replaces counting with typed SQL read-back. D-13 pins the two routes that actually stay usable in production:
schemaless `JSONEachRow`, and `bypassRowBinary=true` with `Struct` records — the more common CDC shape and
completely untested today. That second route is also the honest proof that the escape hatch plan 03-03's new
error message advertises is real.

Output: one Docker-free type-mapping test class and one ClickHouse-backed round-trip test class. No main-code
change: RESEARCH confirmed `Column.dispatchPrimitive`'s `startsWith` checks are already correct, so TYPE-01
and TYPE-02 are pin-only.
</objective>
