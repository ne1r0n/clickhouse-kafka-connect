## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| `workflow_dispatch` input -> shell and script (37-01) | The `version` choice is operator input that must never become shell or script text | One of four words |
| Bump script -> `VERSION` and `fork-anchors.txt` (37-01) | A half-written or mismatched pair breaks the merge gate and the build version | Two file contents |
| Built or downloaded archive -> compare script (37-02) | Archive bytes are untrusted data: read in memory, never extracted or run | Entry names, hashes, manifest text |
| Allow-list file -> compare verdict (37-02) | A catch-all row would make UNALLOWED unreachable | `glob<TAB>reason` rows |
| Baseline tag choice -> compared baseline (37-02, 37-03) | A wrong baseline makes a real change look allowed or a clean build look broken; the baseline is built by that tag's own wrapper on the runner | Tag names, a built archive |
| Release workflow (contents write) -> GitHub release and tags (37-03) | A publish runs only from `custom_build`, after a green `tests.yaml` and a passing compare | Release, tag |
| JUnit XML report text -> Markdown step summary and workflow commands (37-04) | Test names and messages are data that reach the summary and the annotation | Report text |
| `.gitattributes` -> byte guard of an upstream-identical file (37-04) | A conversion rule decides whether the guard sees the bytes upstream has | Line endings |
| Ledger rows and GitHub readings -> the claim that an advisory is closed (37-05) | A row closed without a commit, or an overstated reading, would hide an open defect | Pointers, REST readings |
| Evidence, tests, scripts, commit messages -> repository documents | Environment-specific values or credentials would leak into committed text | Text |
| local repository -> origin and GitHub | No agent step crosses it (A-01, A-10). The one write the phase offers (a scratch-branch push and a dispatch) is a handoff for the user, E-12, pending | Commits, workflow dispatch |
