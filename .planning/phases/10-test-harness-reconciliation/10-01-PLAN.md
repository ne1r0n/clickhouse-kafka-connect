<assumption_delta_decision>
## Assumption-delta checkpoint (advisory)

The detector fired `detected: true` with one `pluralization` signal on HARN-03's "or its cost is measured and the fallback recorded". Re-reading the phase scope confirms a genuine core-assumption change, and it is larger than the signal that surfaced it.

**What changed.** Before this phase, a ClickHouse container's owner was the **test class** — upstream's `@TestInstance(PER_CLASS)` + instance field `db` + `@AfterAll ch.stop()` made "one class, one container" the identity model, and isolation between classes came for free from throwing the container away. After this phase, the container's owner is the **test JVM fork**, and the test class owns only its **database**.

**The noun that is now primary:** the test JVM fork. The test class is demoted from container owner to database owner.

**Decision: `promote`.** The shared-per-fork container becomes the default (`usesSharedContainer()` returns `true`, 25 of 27 classes take it) and per-class container ownership is demoted to a detail of one variant — the opt-out branch, used only where network isolation is structurally required (the two Toxiproxy classes) or where the seam itself is under test (the new opt-out pin class). This is a promote rather than an add-alongside: there is no configuration in which both models are equally primary, and no class chooses per-class ownership for convenience.

**What the promotion costs, recorded:** isolation is no longer free. `tearDown()`'s `DROP DATABASE` becomes load-bearing rather than tidiness, and server-global state — users and grants created by `ClickHouseHelperClientTest`, the `keeper_map` config, `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT` — now outlives the class that created it. That accumulation is an accepted cost of D-01 (RESEARCH Pitfall 4), out of this phase's file scope, and the two consecutive clean full runs in plan 10-02 are the detection mechanism for it.

**Invariant test encoding the generalised intent (adopted, not merely suggested):** `ClickHouseHarnessOptOutContainerTest.optOutClassGetsItsOwnContainerAndDoesNotMoveTheSharedCounter` asserts `sharedContainerStarts() == (sharedContainer() != null ? 1 : 0)`. That assertion goes red the moment a future change reintroduces per-class ownership as a counted start, which is precisely the singular assumption this phase demoted.
