## Execution environment

- **Who runs what.** A dispatched `gsd-executor` runs Task 1 only: it returns the checkpoint with the bundle and stops. The user answers the orchestrator directly; the orchestrator, holding that answer, runs Tasks 2 and 3 **inline** (Phase 11 lesson: the executor correctly refuses approvals relayed by another agent; 11-06-SUMMARY "Executor/orchestrator split").
- **Worktree, not checkout (RESEARCH Pitfall 3, Open Question 4).** `.planning/state.json` is tracked and rewritten by GSD, so `git checkout custom_build` in the main tree can fail. The merge and both pushes happen in `git worktree add /tmp/gsd15/cb custom_build` (the shape Phase 11 used at `/tmp/gsd11/cb`); the main tree stays on `sync/v1.7.0`. The worktree is removed at the end.
- X = the rehearsed SHA recorded in 15-07-SUMMARY.md, which must equal `git ls-remote --heads origin sync/v1.7.0` at the time of the merge. Local `sync/v1.7.0` is ahead of X by planning-tail commits; never merge the branch name.
- GitHub REST API unauthenticated, 60 requests per hour: check `/rate_limit` first; poll `/actions/runs/<id>` every 90 seconds once the id is known, at most 45 minutes; a body without `workflow_runs` is an error. Job logs need admin rights; on a red run the human pastes the failing section.
- Fixed SHAs: `c61d90ce5dfb32ea5876dffacc8bb54d8846739a` (`custom_build` on origin and `pre-v1.7.0-sync`), `6ac2d20cc0c7feacc315b21b322325b4fee25784` (`pre-v1.6.0-sync`), `3b6736e3294781bacadc2513d820a2c52eb609b2` (local `sync/v1.6.0` tip at planning time).
- After this plan, `/gsd-execute-phase`'s own steps (code-review gate, verifier, `/gsd-secure-phase 15`) and `/gsd-complete-milestone` commit to the local tail only (D-14). A finding there that needs a `src/main` change is a new user decision, not a post-publication edit. GSD's `git.create_tag` may create local tags; none is pushed.
