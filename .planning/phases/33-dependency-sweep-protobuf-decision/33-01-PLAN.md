## Execution environment

These rules bind every task in this plan.

- **Where.** Branch `sync/v1.7.0`, the main working tree, with the repository root as the working directory. The plans run sequentially on one tree, with dispatch isolation `none`. `custom_build` is never checked out or committed to.
- **Nothing reaches origin.** Phase 33 pushes nothing. No `git push` of any branch or tag, no `gh pr merge|close|comment|review|edit`, no REST call that writes. Reads go through `git ls-remote`, `git fetch` of a named ref into `FETCH_HEAD` or `refs/remotes/origin/custom_build`, and unauthenticated `curl -sS --fail` GETs against `https://api.github.com/repos/ne1r0n/clickhouse-kafka-connect` (call it R). This plan makes two REST calls. `gh` is installed but not used here; without `-R` it resolves to the upstream repository.
- **Shell.** The shell is zsh. zsh reads `$var:x` as a history modifier: `$r:gradle/...` broke during planning. Write `${var}` before every colon, or run the logic under `/bin/bash -c`. Never name a variable `path`. Run multi-line logic under `/bin/bash -c` or `python3 -I`.
- **Gradle.** Always `env -u TESTCONTAINERS_HOST_OVERRIDE ./gradlew --console=plain ...`. The agent shell exports `TESTCONTAINERS_HOST_OVERRIDE`, which breaks Ryuk. Live runs prefix `CLICKHOUSE_VERSION=latest CLIENT_VERSION=V2`. Never run `./gradlew wrapper`, `spotlessApply` or `spotlessCheck` in the main tree. Never run `git clean`: delete build leftovers one file at a time.
- **Docker.** colima profile `vz`. Check it with `colima list`, never with a bare `colima status` or `colima start`. The docker CLI is not on PATH, so use `D=$(ls -d /opt/homebrew/Cellar/docker/*/bin/docker | tail -1)`.
  - Read the server version with `"$D" run --rm --entrypoint clickhouse clickhouse/clickhouse-server:latest local --query 'SELECT version()'`.
  - Read the image digest with `"$D" image inspect --format '{{index .RepoDigests 0}}' clickhouse/clickhouse-server:latest`.
  - Testcontainers pulls the floating `latest` image before a run, so read both values after each suite run.
- **Full-suite recipe.**
  - Run `rm -rf build/test-results/test`, then `CLICKHOUSE_VERSION=latest CLIENT_VERSION=V2 env -u TESTCONTAINERS_HOST_OVERRIDE ./gradlew --console=plain test --rerun > /tmp/gsd33/exec/<log> 2>&1` and record its exit status. It takes about 3 minutes; allow up to 40 (`test_gate_timeout` 2400 s). It may run in the background; wait for its notification.
  - Tally the counts from the JUnit XML roots (`build/test-results/test/TEST-*.xml`, attributes `tests`, `failures`, `errors`, `skipped`), never from the console.
  - Green means exit 0, failures 0, errors 0 and skipped 18. The 18 are 7 `@Disabled` methods plus 11 `exactlyOnceStateMismatchTest` cases (FORK-DELTA "Named skip inventory").
- **JVM crash, not a test failure.** A run can end with "finished with non-zero exit value 255", or leave a `javacore.*`, `core.*.dmp`, `Snap.*.trc` or `jitdump.*` in the repository root. In that case:
  1. Read the stack in the `javacore`.
  2. Delete each crash file by its name.
  3. Re-run once and record both runs.
  4. If it recurs, run once more with `-PjavaVersion=21` and record that run too.
- **Anchors mirror.** Run it under `/bin/bash -c`. Read `.planning/scripts/fork-anchors.txt` row by row (TAB-separated `path pattern count id`, skipping empty and `#` lines). For each row, compare `grep -cF -e "$pattern" "$file"` with the count. Print `rows=N bad=M` and one `ANCHOR MOVED` line per mismatch. At planning time (HEAD `db47298e`) it printed `rows=131 bad=0`.
- **Origin re-read rule.** Before every PR merge and at every gate, re-read `git ls-remote origin refs/heads/custom_build`. If it differs from E-01's `origin_custom_build`, STOP: merge nothing more, record the new tip, and report to the orchestrator. The user decides how to absorb it; the proposal is a `git merge --no-ff` of the fetched tip, never a rebase.
- **PR-head rule.** Fetch `refs/pull/N/head` immediately before merging it. Accept it only if all four hold:
  - the author is `dependabot[bot]`;
  - it has one parent, equal to `origin_custom_build`;
  - its changed files are exactly the expected ones;
  - the version change is exactly the expected one.

  The research-time heads are orientation only. A rebased head that passes these checks is fine; record `rebased_since_research: yes`. A different target version, an extra file or a different author means STOP and report, because that changes the scope.
- **Commits.**
  - Stage only the explicit file list (`git add <file>`). Never `git add -A`, `git add .` or `git commit -a`.
  - Never stage `.planning/config.json` (it is dirty before the phase starts), `.planning/STATE.md` or `.planning/state.json` in a task commit.

- **Dirty tree.** At the start, `git status --porcelain` may list only paths under `.planning/`. Any other modified or untracked path stops the task before the tag is created.
- **Scratch.** Use `/tmp/gsd33/exec/` (`mkdir -p`). Extract the archive into a fresh empty directory `/tmp/gsd33/arch-19/`: `rm -rf` it, then `mkdir`. The archive is build output, so treat it as data and run nothing from inside it. Nothing in scratch is committed.
- **Evidence entry format.** Each entry has these parts, in order:
