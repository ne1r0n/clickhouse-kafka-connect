## Overview

Bring the fork's workflows current and get a trustworthy integration-test signal, without touching connector code or ClickHouse client `0.10.0`. The release-path workflows build with the project's Gradle wrapper and run only SHA-pinned actions, a dry run proves them, and a fork-owned nightly runs `integrationTest` on ClickHouse `latest` × client V2 in local Docker while upstream's `integrationTests.yaml` stays byte-identical and disabled. Publish `v1.7.0_gg5` with CI green on the published SHA.

No connector code changed: `git diff v1.7.0_gg4 v1.7.0_gg5 -- src/main` is empty. The release phase stopped its review at the three-round cap with two Info findings fixed and not re-reviewed, accepted by the user.

## Phase Details

### Phase 30: Release Workflows & Pin Guard

**Goal**: The fork's three release-path workflows run current, SHA-pinned actions only. `pre-release.yaml` and `release.yaml` build the Confluent archive with the project's own Gradle wrapper through `setup-gradle`, so the `verifyConfluentArchive` finalizer runs on the release path too, and both create the GitHub release with `gh release create`, attaching that archive. A dry run proves both release paths build and attach the archive without creating a release or a tag. A Docker-free guard fails whenever a fork-owned workflow uses an unpinned action, so the Phase 31 nightly is written under it. No connector code changes.

**Depends on**: Nothing in this milestone. Phase 29 shipped `v1.7.0_gg4` (`21c51598`). `release.yaml`, `pre-release.yaml` and `increment-version.yml` are byte-identical to upstream at both `v1.7.0` and `a6f1df83` (measured 2026-10-24). `pre-release.yaml` still runs `gradle/gradle-build-action@v2` with `gradle-version: '7.4.2'` (DEPS-F4). `release.yaml` already uses `gradle/actions/setup-gradle@v6`, by tag. Both release files use `actions/create-release@v1` and `actions/upload-release-asset@v1`, and all three use `@v3`-era actions.

**Requirements**: CIG-01, REL-01, REL-02, REL-03, REL-04, REL-05

**Success Criteria** (what must be TRUE):

  1. *[Docker-free]* A guard test reads every file under `.github/workflows/` except the upstream-identical `integrationTests.yaml`. It fails, naming the file and the line, on any `uses:` that is not a full 40-hex commit SHA with a version comment: a tag, a branch, a short SHA, or a missing comment. It discovers the workflow files from the directory, so a new workflow is covered without editing the guard. Each unpinned form was seen red on a fixture, and the guard was seen red on the unchanged release workflows before they were pinned (CIG-01).
  2. *[Docker-free]* `release.yaml`, `pre-release.yaml` and `increment-version.yml` pin every action by full SHA with a `# vX.Y.Z` comment, and they pass the guard (REL-02). Neither release workflow contains `gradle-build-action`, a `gradle-version:` input or `7.4.2`. Both set up Gradle with `gradle/actions/setup-gradle` and build with `./gradlew createConfluentArchive` (REL-01, REL-03).
  3. *[Docker-free]* No workflow uses `actions/create-release` or `actions/upload-release-asset`. Both release workflows create the release with `gh release create` and attach `build/confluent/clickhouse-kafka-connect-<VERSION>.zip`. `pre-release.yaml` marks the release a prerelease, and `release.yaml` does not (REL-04).
  4. *[CI, operator]* The user dispatches `pre-release.yaml` and `release.yaml` in dry-run mode on the pushed scratch branch. Each run is green: it builds the archive with the wrapper's Gradle, passes `verifyConfluentArchive`, and exercises the attach step on the archive it built without publishing. Afterwards origin has no new published release and no new tag, read from the REST API and `git ls-remote --tags` before and after the runs (REL-05).

Its first manual run happens after publication, in Phase 32 (NIT-03, moved by D-02). Upstream's `integrationTests.yaml` stays byte-identical to upstream and disabled, and a guard pins its bytes. ## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**

- The pin guard (CIG-01) was seen red on the unpinned release files before they were pinned, and the nightly was written under it (Phase 30).
- The release dry run is ref-derived: it builds and attaches the archive to a throwaway draft and creates no release and no tag (Phase 30).
- The integration harness moved to Confluent's Java 17 `cp-server-connect:7.9.6` plus the pinned datagen plugin, taking `integrationTest` from 54 of 54 failing to 54 of 54 passing on `latest` × V2. The user accepted that no skip list is needed (E-06b, Phase 31).
- Upstream's `integrationTests.yaml` stays byte-identical and disabled, pinned by a SHA-256 plus length guard (NIT-02, Phase 31).
- NIT-03 moved from Phase 31 to Phase 32 (D-02): GitHub dispatches a workflow only from the default branch, and the nightly reaches `custom_build` only at publication.
- The nightly is variable-gated (`NIGHTLY_ENABLED`) and was enabled by the operator only after its first green manual run (Phase 32).

**Issues Resolved:**

- DEPS-F4: `pre-release.yaml` no longer builds with Gradle `7.4.2`; both release paths use the wrapper through `setup-gradle`, so `verifyConfluentArchive` runs on the release path too.
- `actions/create-release` and `upload-release-asset` (archived) are replaced by `gh release create`.
- The fork's integration tests had no trustworthy signal; the nightly's first manual run (40474535605) ended green with 63 tests, 0 failures, 9 skipped.
- `increment-version.yml`'s `semver.inc` defect (`vnull` for `_ggN` versions) was measured and recorded.

**Issues Deferred:**

- Phase 30 review advisories left open: WR-01 (shared `release-publish` concurrency group can cancel a queued publish), WR-02 (the pin guard tests only `uses:` lines), WR-03 (dependabot comment overstates the guard) and IN-01..IN-04.
- Phase 31 review advisories left open: WR-01 (`failed_tests_summary.py` prints "No failed tests." when every report is unreadable), WR-02 (Markdown escaping misses `<`, `&`, `[`, `*`, `\`), WR-03 (byte guard can fail on autocrlf Windows clones) and IN-01..IN-03.
- Phase 32 review stop rule: the three-round cap was reached with IN-09 and IN-10 fixed and accepted unreviewed.
- The real publish path was never exercised for gg5: no GitHub release exists, only tags. Dry runs were green.

**Technical Debt Incurred:**

- `release.yaml` and `pre-release.yaml` duplicate about 180 lines.
- `increment-version.yml` still writes `vnull` for `_ggN` versions (CHANGELOG Known Issues).
- `NIGHTLY_ENABLED` ordering rests on the operator's report, because the unauthenticated REST API cannot read repository variables.
