<objective>
Make the connector work against ClickHouse 26.9+ (the current `latest`, 26.9.12.8) without changing the pinned client 0.9.6: force `network_compression_method=lz4` on every client the connector builds (D-17).

Purpose: 26.9 changed the server default `network_compression_method` from LZ4 to ZSTD. With `compress=1` (client 0.9.6's default for responses) the server now returns ZSTD native blocks (method byte `0x90`), which 0.9.6 cannot decode — `Invalid LZ4 magic byte: '-112'`, surfacing as `Connection to ClickHouse is not active`. The wave-1 post-merge gate went 281/654 red on this alone. Production runs 26.3 today (LZ4) and would break on its first upgrade to 26.9+. Raw-HTTP probes already proved that sending `network_compression_method=lz4` makes 26.9 respond with byte-identical `0x82` LZ4 framing to 25.8.

Output: one targeted change in `ClickHouseHelperClient`, a Docker-free pin test, a live round-trip test, and one `docs/FORK-DELTA.md` ledger row.
</objective>
