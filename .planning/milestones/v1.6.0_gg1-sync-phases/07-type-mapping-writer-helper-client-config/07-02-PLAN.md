<objective>
Re-thread the two fork behaviours that live in the helper client onto upstream's rewritten describe and table-discovery code: server-side table filtering via `match(table, '<regex>')`, and the DESCRIBE sub-column skip re-expressed over upstream's loop-local `List<Column>` instead of a `Table`.

Purpose: `targetTableFilter` is one of the five fork behaviours that vanish with no conflict marker and no compile error — the chain from config through the writer's builder call into the helper client's query construction is four links long, and breaking any one of them silently disables filtering while the build stays green. The describe skip is the behaviour upstream's immutable `Table` genuinely forced a redesign on: the `Table` no longer exists while the loop that needs it is running.
Output: a compiling tree in which a configured filter reaches the `system.columns` query, sub-column DESCRIBE rows are skipped by the fork's structural rule, and every reader in the file decodes as UTF-8.
</objective>
