## Planner decision recorded here (PD-01) — the sixth build addition

`06-PATTERNS.md` flags, and CONTEXT.md/RESEARCH.md's "five fork build additions" list does not cover, that the fork carries a Spotless `java { }` configuration block calling `importOrder()` and `removeUnusedImports()`, plus a companion registered `removeUnusedImports` task (fork lines 374-386), while upstream applies the Spotless plugin through its catalog alias with **no** Spotless configuration block at all (grep-confirmed: the only Spotless hit upstream is the plugin alias line). Left unaddressed this block disappears with no conflict marker and no compile error — Spotless would silently run with default settings.

**Decision: keep both, verbatim.** Rationale: (1) `.claude/CLAUDE.md`'s Code Style section documents the Spotless import-order configuration and the `gradle removeUnusedImports` task as project conventions, so dropping them contradicts checked-in project instructions; (2) losing the block changes what `spotlessApply` and `spotlessCheck` do across the whole tree, a behaviour change this milestone did not scope; (3) it is additive and costs no new conflict surface, since `build.gradle.kts` is already a permanently fork-modified file under D-16. The Spotless plugin *version* still takes upstream's catalog value `8.10.1` per BLD-08 — this decision concerns the configuration block, not the version.

Reversibility: reversible. If a future sync wants upstream's defaults, deleting the block is a two-hunk revert with no downstream dependency.
