# Phase 23 Behaviour Ledger

**Purpose:** one place that lists every behaviour change made in Phase 23 (Declared-Nullability Hardening & Review Closure), so that Phase 24 can write the `1.7.0_gg3` CHANGELOG section, complete FORK-DELTA and write `docs/ROLLOUT-v1.7.0_gg3.md` (ROLL-03). Phase 23 writes no CHANGELOG, VERSION or ROLLOUT text.

**Source plans:** 23-02 (L-49), 23-04 (L-50), 23-05 (L-51)

**How to read it:** IDs continue after the Phase 22 ledger's L-48. Test references are `Class` or display-name prefixes. The ledger holds test names, decision IDs and message formats only, never record data.

**Destination key:** CHANGELOG = the `1.7.0_gg3` section of `CHANGELOG.md`; FORK-DELTA = a row or Known costs item; ROLL-03 = an item in `docs/ROLLOUT-v1.7.0_gg3.md`.

| L-49 | 23-02 | `DeclaredNullability` null totality (COLS-12). | L-50 | 23-04 | `DeclaredNullability.normalise` is quote-aware (COLS-13). Before: a backtick-quoted Tuple element name holding a literal backslash-n or a real newline did not pair, because the plain replace of the line break also ate the backslash-n inside the name. The fallback WARN `(structure mismatch)` fired at every DESCRIBE and the root kept DESCRIBE's nullability, so for a `Nullable(Tuple)` every insert failed with `CANNOT_READ_ALL_DATA` (R-02 live). After: `normalise` turns only the server's line break (a lone backslash-n outside quotes) into a space, the name pairs, no WARN fires, the declared nullability applies and the row round-trips. | L-51 | 23-05 | Unpaired-element WARN in `DeclaredNullability` (COLS-14), discovery on both clients. New WARN, format `Declared Tuple element(s) {} of column {} of table {}.{} (declared type {}) have no matching DESCRIBE sub-column; applying the declared nullability to the elements that paired`, logged once per affected root at every DESCRIBE, with no dedup and no static state. Before: a declared Tuple element with no matching DESCRIBE sub-column was silently ignored and the declared nullability applied to the elements that paired.
