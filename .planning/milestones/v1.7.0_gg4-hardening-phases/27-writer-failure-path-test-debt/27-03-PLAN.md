## Decisions recorded in this plan

- **The text and its home (Claude's discretion).** The lookup-miss text is `Enum label not found for column %s` and the no-content text is `No content in enum column %s` (D-07's wording). Both are private static final constants in Column (AGENTS.md: extract strings). They are not shared with the writer's metadata strings, because Column sits in the mapping package and the writer's constants are private to it.
- **Research F-3.** No existing test asserts the NPE class for an unknown label, so D-06's "expectations change from NPE to IllegalArgumentException" is met by new rows, each seen red first. `WriterFailureClassificationUnitTest.UNKNOWN_ENUM_LABEL` pins only the outcome (NON_RETRIABLE), which does not change, so that row stays byte-identical. The only existing expectation that changes is `NO_ENUM_CONTENT_MESSAGE` (D-07).
- **CONTEXT deviations, recorded.** Two CONTEXT statements do not match the code, and E-07 records both under `context_deviations:`. Neither reopens a locked decision. (1) D-06 says the `UNKNOWN_ENUM_LABEL` expectations in WriterValueFreeFailureUnitTest and WriterFailureClassificationUnitTest change from the NPE class to `IllegalArgumentException`. In the code, WriterValueFreeFailureUnitTest has no unknown-label row, and `WriterFailureClassificationUnitTest.UNKNOWN_ENUM_LABEL` asserts only `RetryClass.NON_RETRIABLE` (research F-3). So no existing expectation changes class: the class pins are the new rows of this plan, and `UNKNOWN_ENUM_LABEL` stays byte-identical. (2) D-01 gives the project's Jackson as 2.21. `gradle/libs.versions.toml` pins `jackson = "2.22.4"` (research F-8). D-01's rationale ("Jackson 2.12+") still holds, and E-02 already records the version.
- **Not split, despite the 120k estimate (scope).** The estimate is low-confidence (no calibration samples), and most of it is Gradle and verify output. Task 1's red edits stay uncommitted until Task 3's single `fix(27-03)` commit, which carries the pins, the fix, the anchors and the documents together. A split would leave uncommitted red work across a plan boundary. The plan already holds WRT-18 alone, the first half of step 3 in the locked order, so a split would gain no freedom in the order. Every file in `files_modified` is edited.
- **Research Open Question 1, taken as recommended and flagged to the user.** The `IllegalArgumentException`'s own text is withheld by `WithheldMessageException` on the writer path, so an operator never reads it. They read the class and the column, which the `DataException` prefix already named. ROADMAP criterion 3 ("a message that names the column and a lookup-miss cause") is therefore proven at `Column` level (the exact text) and at writer level (the class). E-07 and ledger row L-54 state the limit. Making the text visible would need a pass-through type thrown from Column, a different decision from D-06 that the user may take later.
- **Pitfall 6.** The null-label row uses a Column built by `Column.extractColumn` (a production `HashMap`). The writer rows build their enum map as `new HashMap<>(Map.of("a", 1))`, because `Map.of(...).get(null)` throws an NPE that is not the bug being fixed.
