## Decisions recorded in this plan

- **The entries (D-04, Claude's discretion on the layout).** The nine goal characters, plus three extra entries: `ctl` (a control with no escaped character, so every premise has a structural baseline), `ap` (an apostrophe: research measured that an apostrophe enum label followed by another label unmaps the table today, research Open Question 2, recommended pinned) and `btbsn` (the 23-REVIEW WR-01 shape, so the real server literal for the NAME-01 pin is captured, as WR-01 asks). Names are `r<fragment>z` at the root and `x<fragment>y` for elements and labels; the root carries `DEFAULT 99` because plan 28-04 pins the doubled-form root as storing its DEFAULT.
- **One names table and one enum table per entry.** A double quote in a name unmaps the whole table today and an apostrophe label does too. Separate tables per entry and per kind keep one failure from hiding the current form of another cell.
- **Server premises, not server formatting, gate the suite.** The in-suite live test asserts only what holds before and after the fix: the decoded JSON names carry the raw fragment where the control carries `_`, and the label appears in the server's single-quote escaping. The byte-for-byte comparison with the committed rows is the drift premise, tagged `describe-drift` and kept out of `test` (the Phase 26 WR-02 precedent: a floating `latest` must not turn the suite red for a formatting change).
- **The current form is the production describeTable's, per client.** The live test builds one helper client with `client_version=V2` and one with `V1` explicitly, whatever `CLIENT_VERSION` says, and reads the names from the Column tree each describeTable returns. The V1 cells are the measured pre-fix V1 forms that the Phase 29 table needs (the connector's own default client is V1, `ClickHouseSinkConfig.java:331`). The one manual `CLIENT_VERSION=V1` run that the ROADMAP requires is a post-fix run in plan 28-05.
- **A server that rejects a matrix DDL stops the plan.** The matrix shape is a planning input of plans 28-03 to 28-05 (their case counts). If `CREATE TABLE` fails for any entry, record the code and stop for a re-plan.
- **Test-only preparation for plan 28-03 (2026-10-23 revision, checker scope_sanity).** The ROADMAP binds NAME-03 and NAME-04 to one commit, so plan 28-03's fix commit cannot be split; what can precede it is the test support that is true and green on both sides of the decode. This plan therefore adds `RawNameMatrix.assertDiscoveredUnderRawNames` (the matrix's discovery assertion, beside `assertServerPremises`) and the two raw-name constants of `DeclaredNullabilityFixtures`, and rewords the Javadoc of `BACKSLASH_N_ELEMENT` and `REAL_NEWLINE_ELEMENT` to a statement about the server's JSON that holds before and after the decode. None of them is called by a test of this plan, so every count below is unchanged. They are entries S-01 and S-02 of plan 28-03's named exemption list (the Javadoc of two existing members changes, their values do not), with S-03 this plan's `resourceLines` refactor.
