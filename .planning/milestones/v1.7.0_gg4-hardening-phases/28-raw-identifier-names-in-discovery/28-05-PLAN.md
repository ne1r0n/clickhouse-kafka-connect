## Decisions recorded in this plan

- **The scan (D-01, research Pattern 4 and finding 1).** A label-only unescape of the current split is not enough: the split itself toggles on an escaped apostrophe and mis-groups, which today unmaps the table with a `NumberFormatException`. So `extractEnumValues` becomes one escape-aware scan inside `Column`. It decodes the JSON layer with the `DeclaredNullability.unescapeJsonLayer` helper that plan 28-03 shipped in the same package (research Open Question 1, recommended: no new file, and the label scan and `normalise` cannot disagree). The edit stays inside `Column`'s enum-label parsing, so D-02's guard holds; any other src/main edit stops for a user decision.
- **The unread escapes (research A1).** `\n`, `\t` and `\r` become the characters, as in `normalise`; any other backslash pair becomes the character after the backslash, as `ClickHouseColumn.of` does for names. NUL, backspace, form feed and other control characters were not measured; a label holding one fails as a lookup miss (loud), which Known costs item 11 states.
- **The legacy-form pin.** A value in the key form the pre-fix code built (`RawNameMatrix.legacyLabelKey`, which E-04's check c2 measured) now fails loudly as the Phase 27 lookup miss. Pinning it makes the enum-label outcome Phase 29 states measured. Entries whose legacy key equals the raw label (`ctl`, `bt`, `na`) have no such case.
- **The documents in this commit (ROADMAP order step 6).** See plan 28-03's decision "NAME-07's documents land in plan 28-05's fix commit". Every figure they cite exists before the commit: E-04, E-07, E-08 and E-09, and this plan's full suite and manual V1 run on the staged tree.
- **The handoff (D-06).** The ledger carries the Phase 29 record; the rollout note itself is Phase 29's. The clean-stop rule is reasoned from the BEFORE/AFTER state machine and labelled so (the Phase 26 E-11 precedent), because no live run here measures a retry across the version change.
- **Tracer.** Task 1 is this plan's tracer: one label from the server's row through the decode, the scan, the writer's code lookup and the insert to a typed read-back.
- **Estimate and file count (2026-10-23 revision, checker scope_sanity, accepted at low confidence).** 160k raw tokens at factor 1.0 with 0 calibration samples, so the figure is directional. It was 180k: this revision drops the whole-file reads of `28-RESEARCH.md` (63,190 characters, for the 2,746 of "Pattern 4") and `Column.java` (25,005 characters, for the 4,148 of the four ranges Task 1 names), measured at about 20k tokens fewer.
