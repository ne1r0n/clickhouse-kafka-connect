## Decisions recorded in this plan

- **The decode mechanism (Claude's discretion).** A streaming read of the row with `OBJECT_MAPPER.createParser(json)`: for the `name` field the decoded text, for every other string field the literal text between its quotes, sliced as `json.substring(start + 1, end - 1)` with `start` from `currentTokenLocation().getCharOffset()` and `end` from `currentLocation().getCharOffset()` after `getText()` finishes the token; every non-string value through `readValueAsTree()`. The values go into an `ObjectNode` that `OBJECT_MAPPER.treeToValue(node, ClickHouseFieldDescriptor.class)` binds, so every binding rule of today (snake_case names, a failure on an unknown property, `0`/`1` for `is_subcolumn`) is the databind's and unchanged. Research verified the slice to be byte-identical to today's `fromJsonRow` on all 272 committed fixture rows; `DescribeFixtureSnapshotUnitTest` and `DescribeFixturesUnitTest` keep that proof in the suite. A line that is not a JSON object goes to `OBJECT_MAPPER.readValue(json, ClickHouseFieldDescriptor.class)` unchanged, so it fails as it does today. An `IOException` that is not a `JsonProcessingException` (unreachable for a `String` source) is rethrown as `JsonMappingException.from((JsonParser) null, <fixed message constant>, e)`, so the checked signature that `DescribeTableBuilder.addRow` and the describe paths rely on stays.
- **The normalise shape (Claude's discretion).** `unescapeJsonLayer` is total: `\\`, `\"`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t` and `\uXXXX` with four hex digits become the character; any other or truncated escape is copied as it is. The quote pass consumes a backslash with the character after it inside a quote, so an escaped backtick or apostrophe never closes the quote; an unterminated quote copies the rest as decoded. Both are single linear passes with no exception path. `ESCAPED_NEWLINE` stays public (tests read it, and the type text still carries it).
- **The shared JSON-layer helper (research Open Question 1).** `unescapeJsonLayer` is a package-private static of `DeclaredNullability`, the class this commit rewrites, so plan 28-05's enum-label parser in `Column` (same package) calls it and the two parsers cannot disagree. No new file.
- **The changed pins keep the server's JSON text in their rows.** `DeclaredNullabilityTest.row(...)` writes names into JSON as the server does, so `BACKSLASH_N_ELEMENT` and `REAL_NEWLINE_ELEMENT` stay the JSON text of the name (their values do not change; plan 28-02 reworded their Javadoc, S-01 and S-02). The two constants plan 28-02 added carry the raw names that discovery now yields: `BACKSLASH_N_ELEMENT_NAME` (Java `"a\\nb"`: a, backslash, n, b) and `REAL_NEWLINE_ELEMENT_NAME` (Java `"a\nb"`: a, line feed, b). Expected flag-map keys, the twins' Kafka field and lookup, and the drift test's nested key use the raw names.
- **The expected normalise literals.** They are derived by the rule (decode the JSON layer, then the quote pass), listed in Task 2, and checked by the red-first run on the unchanged production and the green run on the fix. A literal that the rewritten `normalise` does not produce is re-derived by the rule; output is never pasted in as the expectation. The unterminated-quote row changes too: research expected it unchanged, but decoding the layer turns its backslash-n into a line feed inside the open quote, which the rule copies.
