<objective>
Make `targetTableFilter` and `describeTable` — the two pieces of table discovery the fork added on top of
upstream — provably correct on ClickHouse `latest`, by extracting both pieces of inline logic into
directly-testable helpers and pinning them with Docker-free unit tests plus ClickHouse-backed live tests.

Purpose: FILT-01..04 and DESC-01..04 are today's blind spots. The `showTables` filter clause and the
`describeTable` sub-column skip rule are both inline expressions — one duplicated verbatim in two methods,
neither reachable from a test — so an escaping bug or a new ClickHouse sub-column shape surfaces only as a
mysterious runtime failure in a production CDC pipeline. This plan also resolves the TYPE-07 identifier half,
because the two unguarded `InputStreamReader`s Phase 1 deferred (`ClickHouseHelperClient.java:370` and
`:417`) only ever read DESCRIBE output — column names, `Enum` members, DEFAULT expressions — never record
values.

Output: `shouldSkipDescribeRow(...)` and `buildTableFilterClause(...)` in `ClickHouseHelperClient`, two new
fork-only test classes, the `warn` to `error` log-level flip in both describe methods, the conditional
UTF-8 charset fix, and the corrected FILT-02 wording in REQUIREMENTS.md.
</objective>
