<objective>
Turn the RowBinary path's handling of `JSON`, `Dynamic` and every other unhandled column type from an
unactionable failure into an actionable one, thrown from connector code before a single byte reaches
ClickHouse, and pin it at both the unit and the live level.

Purpose: today `doWriteColValue`'s `default:` branch logs and writes ZERO bytes, so the caller keeps streaming
the next column into a desynced RowBinary stream. Live probing established the ground truth precisely: under
default config `validateDataSchema` fires first and throws a bare data-schema-validation failure that says
nothing actionable, and with `bypassSchemaValidation=true` the desynced stream is rejected server-side with a
cryptic read-after-eof protocol error. Neither state is silent, so this phase's improvement is message clarity
and where in the stack the failure originates — which is exactly why a test asserting only the exception TYPE
would pass before and after and prove nothing.

Output: two small changes in `ClickHouseWriter` (D-01 items 1 and 2), a Docker-free unit class pinning both
gates, and a ClickHouse-backed class proving the failing insert leaves zero rows and that the advertised
escape hatch actually works.
</objective>
