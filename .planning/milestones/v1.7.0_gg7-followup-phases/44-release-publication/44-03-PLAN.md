## Executor boundary (read first)

**This plan is ORCHESTRATOR-INLINE.** It is not dispatched to a `gsd-executor` as a whole. A `gsd-executor` that receives this plan stops at once and returns `## CHECKPOINT REACHED` with the text "44-03 is orchestrator-inline: the orchestrator must spawn a fresh gsd-code-reviewer per round; an executor cannot satisfy RLS-03's independent review", changing nothing. The only executor work in this plan is a fix-only dispatch (Task 2 step 2), whose prompt says that the executor applies the named fixes and does not review.

## Execution environment

Plan 44-01's "Execution environment" (decisions O-1 to O-11, names, nothing reaches origin, shell, hygiene, scratch, commits, scope, time-scoped verify clauses, evidence format, STOP rules) applies. `RV=${PH}/44-review-check.py` is the schema gate (`round`, `rounds`, `disposition`). `R=${PH}/44-REVIEW.md` (inside this plan's verify blocks `R` names the review file, not the repository), `DS=${PH}/44-REVIEW-DISPOSITION.md`.

- **Who runs what.** The orchestrator runs Tasks 1 to 3 inline. It spawns `gsd-code-reviewer` with the Agent tool, one fresh agent per round, with the brief as the prompt (omit `model=` when the configured reviewer model is `inherit` or empty). - **Review attestation (agentId per round).** Every brief tells the reviewer to write, directly under its `## Round <n>` heading, the line `reviewer_agent_id: pending`. When the Agent tool returns, the orchestrator replaces `pending` with the identifier that the Agent tool returned for that spawn (its `agentId`), before the round is committed, and records the same value in the evidence (`reviewer_agent`: E-08 `round 1 agentId=<id> (gsd-code-reviewer spawned by the orchestrator with the Agent tool, fresh context)`; E-09 `round 2 agentId=<id>; round 3 agentId=<id>` for every later round, or `none (round 1 was clean)`). Each round is a new spawn, so the ids differ; a resumed or reused agent is not a fresh round. `python3 -I "${RV}" agents "${R}" --expect-ids <ids from E-08 and E-09 in round order>` is part of every gate of this plan: it fails on a missing line, a placeholder (`pending` included), a malformed or repeated id, or a mismatch with the evidence. Residual, stated as it is: the orchestrator types (copies) the id from the Agent tool's returned value; the gate proves the id is present, well-formed, distinct per round and the same in the review and the evidence, and the Agent tool's own record is what shows the spawn happened. An executor cannot satisfy this gate: it has no Agent tool, so it has no agentId to give, and its own reading is never a round.
