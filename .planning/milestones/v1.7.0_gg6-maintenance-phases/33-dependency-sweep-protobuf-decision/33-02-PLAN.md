## Execution environment

The rules of plan 33-01's "Execution environment" apply unchanged. They are restated here so this plan stands alone.

- **Where.** Branch `sync/v1.7.0`, the main working tree, with the repository root as the working directory. Execution is sequential, with dispatch isolation `none`. `custom_build` is never checked out or committed to.
- **Nothing reaches origin.** No `git push`, no PR action, no writing REST call. Reads are `git ls-remote`, `git fetch` of a named ref, and unauthenticated `curl -sS --fail` GETs against R = `https://api.github.com/repos/ne1r0n/clickhouse-kafka-connect`. This plan makes at most four REST calls. `gh` is not used.
- **Shell.** zsh. Write `${var}` before every colon, or run under `/bin/bash -c`: zsh reads `$var:x` as a modifier. Never name a variable `path`.
- **Gradle.** Always `env -u TESTCONTAINERS_HOST_OVERRIDE ./gradlew --console=plain ...`. Live runs prefix `CLICKHOUSE_VERSION=latest CLIENT_VERSION=V2`. Never `./gradlew wrapper`, `spotlessApply` or `spotlessCheck` in the main tree. Never `git clean`.
- **Docker.** colima profile `vz` (`colima list`). Use `D=$(ls -d /opt/homebrew/Cellar/docker/*/bin/docker | tail -1)`.
  - Read the server version with `"$D" run --rm --entrypoint clickhouse clickhouse/clickhouse-server:latest local --query 'SELECT version()'`.
  - Read the digest with `"$D" image inspect --format '{{index .RepoDigests 0}}' clickhouse/clickhouse-server:latest`.
  - Read both after each suite run.
- **Full-suite recipe.**
  - Run `rm -rf build/test-results/test`, then `CLICKHOUSE_VERSION=latest CLIENT_VERSION=V2 env -u TESTCONTAINERS_HOST_OVERRIDE ./gradlew --console=plain test --rerun > /tmp/gsd33/exec/<log> 2>&1` and record its exit status. It takes about 3 minutes; allow up to 40.
  - Tally the JUnit XML roots under `build/test-results/test/`. Green means exit 0, failures 0, errors 0 and skipped 18.
- **JVM crash.** On "exit value 255", or a `javacore.*`, `core.*.dmp`, `Snap.*.trc` or `jitdump.*` in the root:
  1. Read the javacore.
  2. Delete each crash file by name.
  3. Re-run once and record both runs.
  4. If it recurs, run once with `-PjavaVersion=21`.
- **Anchors mirror.** The bash loop over `.planning/scripts/fork-anchors.txt` from plan 33-01. It prints `rows=N bad=M`; E-05 holds the last value.
- **Origin re-read rule.** Before each merge, `git ls-remote origin refs/heads/custom_build` must equal E-01's `origin_custom_build`. Otherwise STOP and report.
- **PR-head rule.** Fetch `refs/pull/N/head` immediately before merging it. Accept it only if all four hold:
  - the author is `dependabot[bot]`;
  - it has one parent, equal to `origin_custom_build`;
  - its changed files are exactly the expected ones;
  - the version change is exactly the expected one.

  The research-time heads are orientation only: #18 `cb898dc2a9f52ace13c8f9ff8602a37fcc4fb6cd`, #20 `8786723bca5a0a2d0a014d15c15981386da8345d`, #16 `cb3c77187eb5c036dc3d6d155aca4e2cd85dd76f`. A rebased head that passes is fine; record `rebased_since_research: yes`. Anything else means STOP.
- **Merge recipe.** Before writing the message:
  - run `git merge-tree --write-tree --name-only HEAD "$SHA"`, which must print only a tree-OID line;
  - write the message to `/tmp/gsd33/exec/msg-N.txt` with the Write tool.

  Then run `git merge --no-ff -F /tmp/gsd33/exec/msg-N.txt "$SHA"`. The subject is `Merge Dependabot PR #N ({SHA}): {PR title without the chore(deps): prefix}`. The body names the ref, the fetch time (UTC), the author and parent, the requirement ID, and says it is not pushed. End with the Co-Authored-By trailer line the executing session's system reminder specifies.
- **Commits.** Stage explicit files only. Never `git add -A`, `git add .` or `git commit -a`. Never stage `.planning/config.json`, `.planning/STATE.md` or `.planning/state.json` in a task commit.
- **Scratch.** `/tmp/gsd33/exec/`. Archives are extracted into fresh empty directories (`/tmp/gsd33/arch-20/`), and nothing runs from inside them.
- **Evidence entry format.** Exactly as in plan 33-01: the `### E-NN:` heading, `Backs:`, an `sh` fence, a `text` fence of `key: value` lines, a UTC timestamp and a final `Verdict:` line.
