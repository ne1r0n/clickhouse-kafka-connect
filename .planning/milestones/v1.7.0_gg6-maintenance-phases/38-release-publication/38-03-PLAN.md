## Execution environment

- **Who runs what.** The orchestrator runs this plan inline; it is not dispatched to a `gsd-executor` as a whole, because an executor has no Agent tool and its own reading does not count as independent. The orchestrator spawns `gsd-code-reviewer` with the Agent tool, one fresh agent per round, with the brief as its prompt. Fixes are applied by a `gsd-executor` the orchestrator dispatches with a fix-only prompt (the finding IDs with their verbatim `### ID: title` lines, the files it may touch, the owning checks to re-run, and the rule that it does not review). GSD lives under `~/.claude`: any snippet that requires `./gsd-core/bin/lib/...` is pointed at `~/.claude/gsd-core/bin/lib/`. A first `--fix` style run can skip the reviewer when its scope is empty: spawn the reviewer explicitly with the brief.
- Plan 38-01's Execution environment applies (decisions O-1 to O-12, names, nothing reaches origin, shell, scratch, commits, hygiene, evidence format, STOP rules). `RV=${PH}/38-review-check.py` is the schema gate: `python3 -I "${RV}" round|rounds|disposition ...`. `GG5=3a3a15a9ae064ffe09c696b8bb87bce23419d463` is the review's `diff_base`.
- **Files under review.** `docs/ROLLOUT-v1.7.0_gg6.md`; the `1.7.0_gg6` section of `CHANGELOG.md`; `docs/FORK-DELTA.md` (the diff since `GG5` and its consistency with the rest of the file); `docs/ROLLOUT-v1.7.0_gg1.md` (four changed lines since `GG5`: `git diff GG5 HEAD -- docs/ROLLOUT-v1.7.0_gg1.md`); `docs/ROLLOUT-v1.7.0_gg5.md` (the one corrected line). Evidence map: `38-COMMAND-EVIDENCE.md` E-01 to E-07. Completeness checklist: `.planning/phases/35-buffered-offset-commit-under-topic-renaming-smts/35-ROLLOUT-ITEM.md`, `.planning/phases/36-client-0-11-0-audit-bump/36-ROLLOUT-ITEMS.md` and the FUT-05 item of `.planning/phases/34-upstream-tail-merge/34-03-SUMMARY.md`.
- **Fix-text rule.** Every command, number, run id, label or wording a reviewer proposes is checked against the files it describes and the evidence before it is applied. A changed command is re-run; a changed rollback step re-runs the E-07 rehearsal (extract the note's rollback block, run it on a dry-run merge in a new worktree, check `ok`, `VERSION`, the tree and the revert); a changed number is re-measured or re-read from the evidence key it names. Each re-proof is recorded in E-09 as a key `fix_<ID>_reproof`.
- **Owning checks, re-run after any fix.** For the note: `python3 -I "${NC}" all docs/ROLLOUT-v1.7.0_gg6.md --allow GG5 4c69b6fb3b22ab8f7c329383079cc284d3d2e0ae497f3ffb2f0114d171bc6767`, `python3 -I "${DC}" links` over the four documents, and `${H} --strict` over the added lines. For CHANGELOG: `python3 -I "${DC}" changelog CHANGELOG.md <phase-start file> --date <changelog_date> --require ...` as plan 38-01 task 2 ran it. For FORK-DELTA: `python3 -I "${DC}" numbers ...` as plan 38-01 task 3 ran it. Always the anchors mirror.
- **Disposition values.** `fixed`, `rejected` and `deferred`; `open` is not allowed at the end. `rejected` carries its reason in the Source cell (no pipe character in it). `deferred` is only for a finding whose fix needs a protected path (a workflow, a test, the build, `src/`), and its Source cell names the reason, the owner and the re-open trigger; the finding is also listed as `### 38-REVIEW <ID>: <title>` with those three fields under `## Carried to the milestone close`. The disposition may be produced by the code-review disposition step (extract its bash block to a script and run it with `bash`) or written by hand; the checker is the gate either way. With zero findings: `findings: []`, `open: 0`, `total: 0`, an empty table body and the confirmations.
- **Artifacts.** `38-REVIEW.md` (frontmatter `phase`, `reviewed`, `depth: standard`, `diff_base`, `files_reviewed`, `files_reviewed_list`, `findings` with `critical`, `warning`, `info`, `total`, `status`, `rounds`; one `## Round <n>` section per round with its findings and a closing `round: <n> findings: <k>` line; one `## Mandated confirmations (RLS-04)` section per round that contains no `###` heading). `38-REVIEW-DISPOSITION.md` (frontmatter `phase: 38`, `review: 38-REVIEW.md`, `findings:` with `id`, `severity`, `disposition`, `open: 0`, `total: <n>`, `recorded: <ISO>`; the table `| Finding | Severity | Disposition | Source |`; the confirmations; `## Carried to the milestone close` when anything is deferred; `round3_decision:` only if the stop rule fired). Scratch: `/tmp/gsd38/review/brief-r<n>.md`.
