**Decisions at plan time (each cited in the actions).**

- **G-1 Owner groups.** Every difference of the tag-to-tip comparison belongs to an owner, and a row names an owner: third-party owners get anchored literal-prefix globs, connector classes get exact paths. The groups, from research Section 4 (measured on a scratch build of the same trees): `com/clickhouse/client/*` (clickhouse-client and client-v2 0.9.6 to 0.11.0), `com/clickhouse/data/*`, `META-INF/versions/11/com/clickhouse/client/http/*` and `META-INF/versions/11/module-info.class` (the http client's multi-release classes and its module descriptor), `clickhouse-client-version.properties` and `client-v2-version.properties`, `com/github/luben/zstd/*` and `META-INF/versions/22/com/github/luben/zstd/*` and the three natives `darwin/aarch64/libzstd-jni-1.5.7-23.dylib`, `linux/aarch64/libzstd-jni-1.5.7-23.so`, `linux/amd64/libzstd-jni-1.5.7-23.so` as exact rows, `net/jpountz/lz4/*` and `META-INF/maven/at.yawk.lz4/lz4-java/*`, `META-INF/MANIFEST.MF`, and one exact `com/clickhouse/kafka/connect/...` `.class` row per differing connector class. The connector rows map to the seven `src/main` files changed since `v1.7.0_gg5` (`git diff --name-only v1.7.0_gg5 HEAD -- src/main`): the buffer strategies and `ChunkFlusher` (the buffered offset-commit fix and the retriable-code plumbing), `ClickHouseSinkConfig` and its inner classes (the new setting and its validator; the inner classes change through the `InnerClasses` attribute, one is new), `ProxySinkTask` and `Utils` (the retriable-code plumbing), `ClickHouseHelperClient` and its builder (the `createClientV2` fixes and the client name), and `Version` and `SinkTaskStatistics` (the release identity: the inlined `Version.ARTIFACT_VERSION`). A difference that no group explains is not given a row: it is a finding (`unexpected_differences`), the plan stops, and the orchestrator decides.
- **G-2 The candidate is a reference.** `${A}/allowlist-candidate-gg6.txt` holds the 31 rows the research derived. It is never copied into `${PS}`; the real list is derived from this plan's own archives and its glob set is then compared with the candidate. A difference is recorded and explained, not hidden, and does not by itself fail the plan (the compare is the gate).
- **G-3 What "Docker stopped" means here.** The measured Phase 36 and 37 way: `DOCKER_HOST=unix:///nonexistent/docker.sock`, with `docker info` shown to fail under that value, so the Docker-free classes and the whole `testUnit` task run with no daemon reachable, while the colima VM keeps running for the suites. Stopping the VM (`colima stop -p vz`, never the bare default profile) is the stricter alternative and is not used here.
- **G-4 One JVM line.** Both suites run on the same JVM line. Preferred: both on the default JDK 17. If a run needs `-PjavaVersion=21`, both suites run on 21 and the entry says so.
- **G-5 Expected totals** are read from evidence where a key exists (`E37` E-18 `suite_tests` 2231 and `testunit_tests` 1633 give the Docker-only delta 598) and are otherwise the Phase 37 verifier's re-run (`testUnit` 1672 tests, 0 failures, 2 skipped, after the last Java change of the milestone). Phase 38 changes no Java file, so any other `testUnit` total is a finding, not a drift to absorb.
