## Execution environment

- **Who runs what.** A dispatched `gsd-executor` runs Task 1 only. It returns the checkpoint with the bundle and stops. The user answers the orchestrator directly. The orchestrator, holding that answer, runs Tasks 2 and 3 **inline**. Phase 11 lesson: an executor correctly refuses approvals relayed by another agent.
- **Worktree, not checkout.** The merge and the push happen in `git worktree add /tmp/gsd16/cb custom_build`, the shape Phases 11 and 15 used. The main tree stays on `sync/v1.7.0`. `custom_build` is GSD's protected base branch: no bookkeeping commit lands on it, only the merge commit. The worktree is removed at the end.
- **X.** X is the full SHA of local `sync/v1.7.0` at merge time. X0 is the `X0=` line of 16-02-SUMMARY.md. X0..X may contain only `.planning/` commits (the 16-02 SUMMARY and STATE bookkeeping). Any other change re-opens the gate.
- **Fixed SHAs:**
  - `f328fd218dce5b9c652f8872042e922f9686b87f`: `custom_build` on origin, tag `v1.7.0_gg1`.
  - `c61d90ce5dfb32ea5876dffacc8bb54d8846739a`: `pre-v1.7.0-sync` and `v1.6.0_gg1`.
  - `6ac2d20cc0c7feacc315b21b322325b4fee25784`: `pre-v1.6.0-sync`.
  - Origin's heads before the push: `custom_build` and `main`.
- **GitHub REST API**, unauthenticated, 60 requests per hour; `gh` is deliberately absent.
  - Check `/rate_limit` first; at least 15 must remain.
  - Until the run id is known, poll `actions/runs?head_sha=M` every 30-60 seconds for at most 5 minutes. Once it is known, poll `/actions/runs/<id>` every 90 seconds for at most 45 minutes.
  - A body without `workflow_runs` (or, for a single run, without `status`) is an error.
  - Job logs need admin rights, so on a red run the user pastes the failing section.
- **The upstream-sync gate does not apply.** `verify-merge-invariants.sh` requires the second parent to be an upstream release tag. This merge's gate is the allow-list diff plus tree equality (ROADMAP Phase 16 note). The script is not run as this gate and is not edited.
- **Deadline (D-12).** `ubuntu-latest` moves to Ubuntu 26 on 2026-10-19. The push must happen before that date (UTC), on the unchanged `tests.yaml`.
- **After this plan,** `/gsd-execute-phase`'s own steps (code-review gate, verifier, `/gsd-secure-phase 16`) commit to local `sync/v1.7.0` only. A docs change they call for needs a new user-approved publication. It is never an edit to `custom_build`. `git.create_tag` may create local tags; none is pushed.
